# Grimoire のチャット内リンク

Grimoire のチャットに表示されたノートへの `file://` リンクが開けない場合、**リンクの表示と、クリックによるローカルファイルへのアクセスは別の問題**。Obsidian や表示コンポーネント、OS の設定などにより、セキュリティ上 `file://` リンクの起動が制限される場合がある。ただし、この環境での実際の原因は未検証。

## 確認すること

1. リンクに記されたファイルが保管庫内に存在するか、Obsidian のクイックスイッチャーでノート名を検索する。
2. **Obsidian の内部リンク**（例：`[[Unix 盆栽]]`）をチャットに表示した場合にクリックできるか試す。表示コンポーネントによって対応は異なる。
3. リンクがまったく反応しないのか、エラーが出るのか、別のアプリが開くのかを確認する。原因の切り分けに役立つ。
4. ファイル名の空白や日本語が URL エンコードされた `file://` リンクでも開かない場合、表示側の制限が考えられるが、それだけで原因を断定はできない。

保管庫内のノートを参照する場合は、OS の絶対パスに依存する `file://` より、通常は Obsidian の **wikilink** を使う方が適している。クリックできない場合も、リンクに記されたノート名をクイックスイッチャーで検索できる。

## Grimoire の実装で確認できたこと

ユーザーの確認により、対象のファイルは存在する。したがって「ファイルがない」ことは原因ではない。

インストール済み Grimoire の `main.js` では、チャットを Obsidian の `MarkdownRenderer.render` で描画し、内部リンクや Grimoire が識別したファイルリンクのクリックを `workspace.openLinkText` に渡している。一方、このクリック処理には `file://` URL を保管庫相対パスに変換する処理は見当たらない。

そのため、以前の回答で使った絶対パスの `file://` リンクが、この内部リンク処理では期待どおり開けない可能性がある。ただし `file://` のクリックが実際にどの経路で処理されたかは未検証なので、これだけで原因を確定はできない。今後は保管庫内のノートに `[[programming/Unix 盆栽|Unix 盆栽]]` のような wikilink を使う。これが開けるかどうかも実際に確認する。

ユーザーによる確認では、チャット内の `[[programming/Unix 盆栽|Unix 盆栽]]` は開けた。今後、保管庫内のノートは wikilink で案内する。`file://` が開けない原因そのものは未確定。

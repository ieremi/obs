# DateTime

**日付と時刻（時・分・秒）と、UTC からのずれ（オフセット）をあわせて表すクラス。** `Date` のサブクラスで、標準ライブラリ `date` に入っている。

**公式の文書では「DateTime クラスは非推奨と考えられている。Time クラスを使うこと」とされている。** 新しく書くコードでは、ふつうは `Time` を使う。ただし、**昔の日付（暦の改暦をまたぐ日付）** を正しく扱いたいときは、`Date`・`DateTime` が役に立つ（下の「Time との使い分け」）。

- 使う前に `require 'date'` が要る（`Time` は要らない）
- うるう秒は考えない。**夏時間の規則も持たない**（オフセットの数だけを持つ）

## 作る

```ruby
require 'date'

DateTime.new(2026, 11, 1, 9, 30, 0, "+09:00")
# => #<DateTime: 2026-11-01T09:30:00+09:00 ((2461346j,1800s,0n),+32400s,2299161j)>
DateTime.new(2026, 11, 1, 9, 30, 0, "+09:00").to_s  # => "2026-11-01T09:30:00+09:00"
DateTime.superclass                                  # => Date

DateTime.parse("2026-11-01T09:30:00+09:00")          # 文字列から（形をおおよそ推測する）
DateTime.iso8601("2026-11-01T09:30:00+09:00")        # ISO 8601 の形だけを読む
DateTime.strptime("2026/11/01 09:30", "%Y/%m/%d %H:%M")
# => #<DateTime: 2026-11-01T09:30:00+00:00 ...>      ← オフセットがないと UTC になる
DateTime.now                                         # いまの時刻（DateTime）
```

- 引数は `年, 月, 日, 時, 分, 秒, オフセット, 改暦日`。省くと 0（オフセットは **UTC**）
- オフセットは、文字列（`"+09:00"`）か、**1 日を 1 とした分数**（`Rational(9, 24)`）で渡す
- 最後の引数を小数にできる：`DateTime.new(2026, 11, 1, 9, 30, 15.5).sec_fraction  # => (1/2)`
- ない日付は `Date::Error`：`DateTime.new(2026, 2, 29)  # => Date::Error: invalid date`。あるかどうかは `DateTime.valid_date?(2028, 2, 29)  # => true` で調べる
- 秒に 60 は使えない（うるう秒なし）：`DateTime.new(2026, 11, 1, 23, 59, 60)` は `Date::Error`。`Time.utc(2026, 11, 1, 23, 59, 60)` は、つぎの日の `00:00:00` に繰り上がる

### `inspect` の中身
`((2461346j,1800s,0n),+32400s,2299161j)` は、

| 部分 | 意味 |
| --- | --- |
| `2461346j` | **ユリウス日**（紀元前 4713 年 1 月 1 日から数えた日の番号。UTC で数える） |
| `1800s` | その日の UTC での秒（0 時 30 分 ＝ 1,800 秒） |
| `0n` | ナノ秒 |
| `+32400s` | オフセット（9 時間 ＝ 32,400 秒） |
| `2299161j` | **改暦日**（ユリウス暦からグレゴリオ暦に変わった日）。既定は `Date::ITALY`＝1582 年 10 月 15 日 |

## 取り出す

```ruby
dt = DateTime.new(2026, 11, 1, 9, 30, 0, "+09:00")
dt.year, dt.month, dt.day    # => 2026, 11, 1
dt.hour, dt.minute, dt.sec   # => 9, 30, 0     （min・second も同じ）
dt.offset                    # => (3/8)        ← 9/24 日
dt.zone                      # => "+09:00"
dt.wday                      # => 0            ← 日曜日（0）〜土曜日（6）
dt.cwday                     # => 7            ← ISO の曜日。月曜日（1）〜日曜日（7）
dt.jd                        # => 2461346      ← ユリウス日
```

## 計算

**`DateTime` の足し算・引き算の単位は「日」**。差は **有理数（Rational）の日数** で返る。

```ruby
dt = DateTime.new(2026, 11, 1, 9, 30, 0, "+09:00")
(dt + 1).to_s                  # => "2026-11-02T09:30:00+09:00"   1 日あと
(dt + Rational(1, 24)).to_s    # => "2026-11-01T10:30:00+09:00"   1 時間あと
(dt >> 1).to_s                 # => "2026-12-01T09:30:00+09:00"   1 か月あと（<< で前）

d = DateTime.new(2026, 11, 2, 12, 0, 0) - DateTime.new(2026, 11, 1, 0, 0, 0)
d                              # => (3/2)    1.5 日
(d * 24).to_i                  # => 36       時間にするには 24 をかける
```

- `Time` は **秒** が単位（`Time + 3600` が 1 時間あと）。**`DateTime` の `+ 1` は 1 日、`Time` の `+ 1` は 1 秒**。まちがえやすい
- 1 時間を `1/24` と書くと、Integer どうしの割り算で **0** になる。`Rational(1, 24)` か `1/24r` と書く

## オフセットを変える

```ruby
dt = DateTime.new(2026, 11, 1, 9, 30, 0, "+09:00")
dt.new_offset(0).to_s          # => "2026-11-01T00:30:00+00:00"   UTC に
dt.new_offset("-05:00").to_s   # => "2026-10-31T19:30:00-05:00"
```

- 同じ瞬間を、別のオフセットで表しなおす。**タイムゾーンの名前（Asia/Tokyo など）は扱えない**ので、夏時間のある地域では、自分でオフセットを決める必要がある

## 文字列にする

```ruby
dt.strftime("%Y年%m月%d日 %H時%M分 %z")  # => "2026年11月01日 09時30分 +0900"
dt.iso8601                                # => "2026-11-01T09:30:00+09:00"
```

- ほかに `rfc3339`、`rfc2822`、`httpdate`、`jisx0301`（和暦の形）など

## Time・Date との変換

```ruby
dt.to_time     # => 2026-11-01 09:30:00 +0900                    （Time）
dt.to_date     # => #<Date: 2026-11-01 ...>                       （時刻を捨てる）
Time.new(2026, 11, 1, 9, 30, 0, "+09:00").to_datetime
# => #<DateTime: 2026-11-01T09:30:00+09:00 ...>
```

## Time との使い分け

| | `Time` | `DateTime` |
| --- | --- | --- |
| すすめ | **ふつうはこちら** | 公式に **非推奨** |
| `require` | 要らない | `require 'date'` |
| 計算の単位 | 秒 | 日（Rational） |
| 暦 | いつでも **グレゴリオ暦**（さかのぼって当てはめる） | 改暦日の前は **ユリウス暦**、あとは **グレゴリオ暦** |
| タイムゾーン | システムの TZ（環境変数 `TZ`）を使える。Ruby 3.1 からは `in:` でタイムゾーンを渡せる | オフセットの数だけ |
| うるう秒 | 扱わない | 扱わない |

### 改暦をまたぐ日付
グレゴリオ暦は、1582 年 10 月 4 日（ユリウス暦）のつぎの日を **10 月 15 日** にして始まった（10 日分とばした）。`Date`・`DateTime` は、この改暦を知っている。

```ruby
(DateTime.new(1582, 10, 4) + 1).to_s   # => "1582-10-15T00:00:00+00:00"   ← 10 日とぶ
Time.new(1582, 10, 4).to_date + 1      # => #<Date: 1582-09-25 ...>
```

- 2 行目：`Time` の 1582 年 10 月 4 日は **グレゴリオ暦** の日付。それを `Date`（改暦前はユリウス暦）に直すと、ユリウス暦の 9 月 24 日になり、1 日足して 9 月 25 日。**同じ「1582 年 10 月 4 日」でも、Time と Date で指す日がちがう**
- 国ごとに改暦の日がちがう。イギリスとその植民地は 1752 年：

  ```ruby
  DateTime.new(1752, 9, 2, 0, 0, 0, 0, Date::ENGLAND).next_day.to_s
  # => "1752-09-14T00:00:00+00:00"    ← イギリスでは 9 月 2 日のつぎが 14 日
  ```

  改暦日の定数：`Date::ITALY`（既定、1582 年）、`Date::ENGLAND`（1752 年）、`Date::JULIAN`（いつまでもユリウス暦）、`Date::GREGORIAN`（いつまでもグレゴリオ暦）
- 公式の文書は、「シェイクスピアとセルバンテスは同じ日（1616 年 4 月 23 日）に死んだ」というよくあるまちがいを例にあげている。イギリスはまだユリウス暦、スペインはすでにグレゴリオ暦だったので、**同じ日付でも、実際には 10 日ちがう**。こういう **歴史の日付** を扱うときは、`Date`・`DateTime` で改暦日を指定する
- 日本は、1873 年（明治 6 年）に太陰太陽暦からグレゴリオ暦に変わった。和暦の旧暦の日付は、Ruby の標準では扱えない

## Rails では
- Rails（ActiveSupport）では、タイムゾーンつきの時刻は **`ActiveSupport::TimeWithZone`**（`Time.zone.now` など）を使う。`DateTime` もいくつかのメソッドが足されているが、ふつうは `Time`・`TimeWithZone` を使う

## 押さえどころ
- `DateTime` は、日付＋時刻＋オフセットのクラス。`Date` のサブクラスで、`require 'date'` が要る
- **公式に非推奨**。ふつうは `Time` を使う
- 計算の単位は **日**（`+ 1` は 1 日、`+ Rational(1, 24)` は 1 時間）。差は Rational の日数
- タイムゾーンの名前・夏時間・うるう秒は扱わない
- **改暦をまたぐ昔の日付** は `Date`・`DateTime` のほうが正しい（Time はいつでもグレゴリオ暦）

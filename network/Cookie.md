# Cookie

Cookieは、サーバーがブラウザーに保存させる小さなデータ。ブラウザーは同じサイトへのリクエストのたびに、それを自動で送り返す。**HTTPはリクエストごとに独立していて前回を覚えていない（ステートレス）ので、ログイン状態などを続けるために使う。**

## やりとりの流れ

```text
1. ブラウザー → サーバー：ログイン情報を送る
2. サーバー → ブラウザー：Set-Cookie でセッションIDを渡す
3. ブラウザー → サーバー：以後のリクエストに Cookie ヘッダーで付ける
```

```http
HTTP/1.1 200 OK
Set-Cookie: sid=abc123; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=3600
```

```http
GET /mypage HTTP/1.1
Host: example.com
Cookie: sid=abc123
```

サーバーは `sid` を手がかりに、自分の側に保存したセッション情報を引く。Cookie自体にはIDだけを入れ、中身はサーバー側に持たせるのが普通。

## 主な属性

| 属性 | 意味 |
| --- | --- |
| `Expires` / `Max-Age` | 有効期限。どちらもなければ**セッションCookie**で、ブラウザーを閉じると消える（セッション復元機能で残ることもある）。 |
| `Domain` | 送り先のドメイン。省略すると、設定したホストだけに送る。指定するとサブドメインにも送る。 |
| `Path` | 送り先のパス。 |
| `Secure` | HTTPSのときだけ送る。 |
| `HttpOnly` | JavaScriptの `document.cookie` から読めなくする。 |
| `SameSite` | 別サイトからのリクエストに付けるかどうか（下表）。 |
| `Partitioned` | 埋め込み先のサイトごとに分けて保存する（CHIPS）。サードパーティCookieの代わりに使う。 |

### SameSite

| 値 | 別サイトからのリクエスト |
| --- | --- |
| `Strict` | 送らない。リンクで遷移してきたときも送らない。 |
| `Lax` | リンクでのページ遷移（GET）なら送る。フォームのPOSTや画像・iframeの読み込みでは送らない。 |
| `None` | 送る。`Secure` が必須。 |

指定がない場合、Chromeなどは `Lax` として扱う。

### 名前の接頭辞

| 接頭辞 | 条件 |
| --- | --- |
| `__Secure-` | `Secure` 付きでHTTPSから設定したときだけ受け付ける。 |
| `__Host-` | さらに `Domain` なし・`Path=/` が必須。サブドメインから上書きされない。 |

## ファーストパーティとサードパーティ

| 種類 | 設定元 | 主な用途 |
| --- | --- | --- |
| ファーストパーティCookie | アドレスバーに表示されているサイト | ログイン、カート、設定の保存 |
| サードパーティCookie | ページに埋め込まれた別サイト（広告、解析、SNSボタンなど） | サイトをまたいだ行動の追跡、広告配信 |

サードパーティCookieは、プライバシーの面から制限が進んでいる。

| ブラウザー | 扱い |
| --- | --- |
| Safari | 2020年から既定でブロック（ITP）。 |
| Firefox | 2022年から既定でサイトごとに分離（Total Cookie Protection）。 |
| Chrome | 2020年に廃止を表明したが延期を重ね、2025年に廃止そのものを取りやめた。利用者が設定で制限する方式。 |

## セキュリティ

| 攻撃 | 内容 | 主な対策 |
| --- | --- | --- |
| セッションハイジャック | セッションIDを盗んでなりすます。 | `Secure`、HTTPS、ログイン時にIDを作り直す。 |
| XSS | 埋め込まれたスクリプトが `document.cookie` を読んで送り出す。 | `HttpOnly`、出力のエスケープ、CSP。 |
| CSRF | 罠サイトから、Cookie付きのリクエストを勝手に送らせる。 | `SameSite`、CSRFトークン。 |
| セッション固定 | 攻撃者が用意したIDを使わせる。 | ログイン時にIDを作り直す。 |

開発者ツールのコンソールにコードを貼らせる詐欺（Self-XSS）も、Cookieの持ち出しが狙いになる。[[ブラウザの開発者ツールでJavaScriptを使う]]

## 制限と他の保存方法

- 1つのCookieはおよそ4KBまで。1ドメインあたりの個数にも上限がある。
- 毎回のリクエストに付くので、大きくすると通信量が増える。[[ウェブサイトのリクエスト数]]

| 保存方法 | サーバーへ自動送信 | 容量 | 主な用途 |
| --- | --- | --- | --- |
| Cookie | される | 約4KB | セッション管理 |
| `localStorage` | されない | 数MB | 画面の設定など、ブラウザー内だけで使うデータ |
| `sessionStorage` | されない | 数MB | タブを閉じるまでの一時データ |

## 歴史

| 年 | 出来事 |
| --- | --- |
| 1994年 | Netscapeのルー・モントゥリが、ショッピングカートのために考案。 |
| 1997年 | RFC 2109で標準化。2000年にRFC 2965。 |
| 2011年 | RFC 6265。実際のブラウザーの動作に合わせた現行の仕様。`SameSite` などを加える改訂（RFC 6265bis）が進んでいる。 |

## 法律との関係

| 地域 | 内容 |
| --- | --- |
| EU | ePrivacy指令とGDPRにより、必須でないCookieには事前の同意が必要。Cookieバナーが広がった理由。 |
| 日本 | 2022年の改正個人情報保護法で「個人関連情報」の第三者提供に本人同意の確認が必要に。2023年6月施行の改正電気通信事業法（外部送信規律）で、利用者の情報を外部に送る場合の通知・公表が義務になった。 |

### 電気通信事業法 第27条の12（外部送信規律）

> **（情報送信指令通信に係る通知等）**
>
> **第二十七条の十二**　電気通信事業者又は第三号事業を営む者（内容、利用者の範囲及び利用状況を勘案して利用者の利益に及ぼす影響が少なくないものとして総務省令で定める電気通信役務を提供する者に限る。）は、その利用者に対し電気通信役務を提供する際に、当該利用者の電気通信設備を送信先とする情報送信指令通信（利用者の電気通信設備が有する情報送信機能（利用者の電気通信設備に記録された当該利用者に関する情報を当該利用者以外の者の電気通信設備に送信する機能をいう。以下この条において同じ。）を起動する指令を与える電気通信の送信をいう。以下この条において同じ。）を行おうとするときは、総務省令で定めるところにより、あらかじめ、当該情報送信指令通信が起動させる情報送信機能により送信されることとなる当該利用者に関する情報の内容、当該情報の送信先となる電気通信設備その他の総務省令で定める事項を当該利用者に通知し、又は当該利用者が容易に知り得る状態に置かなければならない。ただし、当該情報が次に掲げるものである場合は、この限りでない。
>
> 一　当該電気通信役務において送信する符号、音響又は影像を当該利用者の電気通信設備の映像面に適正に表示するために必要な情報その他の利用者が電気通信役務を利用する際に送信をすることが必要なものとして総務省令で定める情報
>
> 二　当該電気通信事業者又は第三号事業を営む者が当該利用者に対し当該電気通信役務を提供した際に当該利用者の電気通信設備に送信した識別符号（電気通信事業者又は第三号事業を営む者が、電気通信役務の提供に際し、利用者を他の者と区別して識別するために用いる文字、番号、記号その他の符号をいう。）であつて、当該情報送信指令通信が起動させる情報送信機能により当該電気通信事業者又は第三号事業を営む者の電気通信設備を送信先として送信されることとなるもの
>
> 三　当該情報送信指令通信が起動させる情報送信機能により送信先の電気通信設備に送信されることについて当該利用者が同意している情報
>
> 四　当該情報送信指令通信が次のいずれにも該当する場合には、当該利用者がイに規定する措置の適用を求めていない情報
>
> 　イ　利用者の求めに応じて次のいずれかに掲げる行為を停止する措置を講じていること。
>
> 　　（１）　当該情報送信指令通信が起動させる情報送信機能により行われる利用者に関する情報の送信
>
> 　　（２）　当該情報送信指令通信が起動させる情報送信機能により送信された利用者に関する情報の利用
>
> 　ロ　イに規定する措置、当該措置に係る利用者の求めを受け付ける方法その他の総務省令で定める事項について利用者が容易に知り得る状態に置いていること。

| 条文の言葉 | Webでの例 |
| --- | --- |
| 情報送信指令通信 | ページに埋め込んだ解析タグや広告タグなど、ブラウザーに情報を送らせる指令。 |
| 情報送信機能 | ブラウザーが、Cookieや閲覧履歴などを外部に送る働き。 |
| 1号（必要な情報） | ページを正しく表示するための情報など。通知はいらない。 |
| 2号（自社の識別符号） | 自社が発行したCookieのIDを自社に送り返す場合。ファーストパーティCookieのセッションIDなど。 |
| 3号（同意） | 利用者が同意している場合。 |
| 4号（オプトアウト） | 停止の手段を用意し、それを公表しているときに、利用者が停止を求めていない場合。 |

つまり、**外部（サードパーティ）に送らせる場合は、原則として送る情報と送信先を通知・公表する**。同意までは必須ではない。

### 個人情報保護法 第2条第7項・第31条（個人関連情報）

> **第二条**
>
> ７　この法律において「個人関連情報」とは、生存する個人に関する情報であって、個人情報、仮名加工情報及び匿名加工情報のいずれにも該当しないものをいう。

> **（個人関連情報の第三者提供の制限等）**
>
> **第三十一条**　個人関連情報取扱事業者は、第三者が個人関連情報（個人関連情報データベース等を構成するものに限る。以下この章及び第六章において同じ。）を個人データとして取得することが想定されるときは、第二十七条第一項各号に掲げる場合を除くほか、次に掲げる事項について、あらかじめ個人情報保護委員会規則で定めるところにより確認することをしないで、当該個人関連情報を当該第三者に提供してはならない。
>
> 一　当該第三者が個人関連情報取扱事業者から個人関連情報の提供を受けて本人が識別される個人データとして取得することを認める旨の当該本人の同意が得られていること。
>
> 二　外国にある第三者への提供にあっては、前号の本人の同意を得ようとする場合において、個人情報保護委員会規則で定めるところにより、あらかじめ、当該外国における個人情報の保護に関する制度、当該第三者が講ずる個人情報の保護のための措置その他当該本人に参考となるべき情報が当該本人に提供されていること。
>
> ２　第二十八条第三項の規定は、前項の規定により個人関連情報取扱事業者が個人関連情報を提供する場合について準用する。この場合において、同条第三項中「講ずるとともに、本人の求めに応じて当該必要な措置に関する情報を当該本人に提供し」とあるのは、「講じ」と読み替えるものとする。
>
> ３　前条第二項から第四項までの規定は、第一項の規定により個人関連情報取扱事業者が確認する場合について準用する。この場合において、同条第三項中「の提供を受けた」とあるのは、「を提供した」と読み替えるものとする。

CookieのIDや閲覧履歴は、それだけでは誰のものかわからないので、多くは「個人関連情報」にあたる。それを受け取る側が手元の会員情報などと結びつけて個人データにすることが想定されるときは、提供する側が、本人の同意が取れているかを事前に確認しなければならない。

| 比べる点 | 電気通信事業法 第27条の12 | 個人情報保護法 第31条 |
| --- | --- | --- |
| 対象 | 利用者のブラウザーなどに外部送信をさせる事業者 | 個人関連情報を第三者に提供する事業者 |
| 求めること | 通知・公表（同意やオプトアウトでも可） | 受け取る側で本人の同意が取れていることの確認 |
| 場面 | 送らせる時点 | 受け取る側で個人と結びつく場合 |

## 自分のブラウザーで観察する

1. 開発者ツールの Application（Firefoxは Storage）→ Cookies を開く。
2. 名前、値、Domain、Path、Expires、HttpOnly、Secure、SameSite を確かめる。
3. Network でリクエストを選び、`Set-Cookie` と `Cookie` ヘッダーを確かめる。
4. コンソールで `document.cookie` を実行し、`HttpOnly` のCookieが出ないことを確かめる。

## 押さえどころ

- Cookieは「サーバーが保存させ、ブラウザーが自動で送り返す」。送り返しが自動なので、CSRFが成り立つ。
- `HttpOnly` はXSSによる盗み出しを防ぐが、XSSそのものは防がない。
- セッションCookieの「セッション」はブラウザーを閉じるまでの意味。サーバーのセッション管理とは別の言葉。
- 「サードパーティ」はCookieの種類ではなく、表示中のサイトとの関係で決まる。同じCookieが、あるページではファーストパーティ、別のページではサードパーティになる。

# ウェブサイトのリクエスト数

**ブラウザなどのクライアントが、サーバーへHTTPで要求を送った回数**。HTML、画像、CSS、JavaScript、APIなどの取得・送信が対象になる。

**ページを1回開くことと、リクエスト1回は同じではない**。

## 1ページで複数のリクエストが発生する

例えば、以下の構成をキャッシュなしで読み込む場合。

| 対象 | リクエスト数（例） |
| --- | ---: |
| HTML | 1 |
| CSSファイル | 2 |
| JavaScriptファイル | 3 |
| 画像 | 10 |
| API呼び出し | 2 |
| 合計 | **18** |

これは説明用の例。実際にはフォント、アクセス解析、広告、リダイレクトなども加わる。HTMLに直接埋め込んだCSSなどは、それ自体の取得リクエストを増やさない。[MDN：HTTPの概要](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)

## PV・訪問者数との違い

| 指標 | 数えるもの |
| --- | --- |
| リクエスト数 | HTTPの要求の回数 |
| PV（ページビュー） | ページが表示された回数。具体的な計測条件は解析ツールによる |
| 訪問者数 | 一定期間に訪れた利用者の数。識別方法はツールによる |
| 転送量 | 実際に送受信したデータ量（MB、GBなど） |

同じ人が1ページを開いても、多数のリクエストが発生しうる。サーバー側の件数には、クローラー、監視、攻撃など、人による閲覧以外の要求も含まれる場合がある。

## どこで数えるかで変わる

| 観測場所 | 見ているもの |
| --- | --- |
| ブラウザの開発者ツール | そのブラウザが読み込んだリソースやAPI通信。外部サービスへの通信も確認できる |
| CDN | CDNに届いた要求。キャッシュから応答した要求も含みうる |
| オリジンサーバー | CDNなどを経由して、実際に配信元へ届いた要求 |
| ホスティングの課金画面 | そのサービスが定義する課金対象の要求 |

**ブラウザの件数、サーバーログの件数、課金対象の件数は一致するとは限らない**。静的ファイル、失敗した要求、外部サービスへの要求などの扱いは、計測・課金の定義を確認する。

## キャッシュとの関係

- **ブラウザキャッシュ**：有効な保存済みデータを再利用できれば、ネットワークへの要求を省ける。
- **再検証**：保存済みデータが使えるかサーバーへ問い合わせる場合は、要求が発生する。`304 Not Modified` は本文の再転送を省く応答であり、リクエストがゼロという意味ではない。
- **CDNキャッシュ**：配信元への要求を減らせるが、ブラウザからCDNへの要求は発生する。

開発者ツールに表示された行でも、メモリ・ディスクキャッシュから取得したものは、ネットワークへ送られていない場合がある。[MDN：HTTPキャッシュ](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)

## 負荷の目安：RPS

**RPS（requests per second）**は、1秒あたりのリクエスト数。

$$
\text{期間の秒数}\times\text{平均RPS}=\text{期間中のリクエスト数}
$$

例：1日86,400件なら、平均は **1 RPS**。ただし、特定の時間に集中すればピークは大きくなる。

負荷は件数だけでなく、処理内容でも変わる。キャッシュされた画像の配信と、データベースを検索するAPIでは、1件あたりの処理負荷が異なる。

## 確認方法

Chromeでは、開発者ツールの **Network** を開いてからページを再読み込みする。

1. フィルターを解除し、記録をクリアする。
2. ページを再読み込みして、要求の件数と一覧を見る。
3. `Img`、`JS`、`Fetch/XHR`などで種類を絞り、何が要求を増やしているか調べる。
4. 転送量、所要時間、キャッシュからの取得も確認する。

**キャッシュ有効時と無効時を分けて測定**する。画面操作やスクロールで追加通信が起こることもあるため、測定する操作・時間をそろえる。[Chrome DevTools：Network](https://developer.chrome.com/docs/devtools/network/)

## 減らす方法

- 不要な画像・スクリプト・外部タグを削除する。
- 適切なキャッシュ設定を使う。
- 必要になるまで画像などの読み込みを遅らせる（遅延読み込み）。
- APIの重複呼び出しや過度な定期取得を減らす。

リクエスト数だけを最小化するより、**表示速度・転送量・サーバー負荷を合わせて評価する**。画像を圧縮しても通常は件数は変わらないが、転送量は減らせる。
